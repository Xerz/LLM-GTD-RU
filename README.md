# LLM-GTD на русском для Codex

Русскоязычная адаптация [оригинального LLM-GTD](https://github.com/mikonos/LLM-GTD) для Codex. Исходный проект распространяется по лицензии MIT; её текст сохранён в [LICENSE](LICENSE). [Английский README оригинала](README.en.md) и [китайский README оригинала](README.zh-CN.md) оставлены для сравнения.

Плагин помогает записывать дела, уточнять следующие действия, вести проекты и ожидания, выбирать подходящее действие и проводить еженедельный обзор. Все инструкции для пользователя, справочники и создаваемые Markdown-списки написаны по-русски. Технические имена папок и файлов оставлены латиницей. Русская система хранится в `memory/gtd-ru/` текущего рабочего проекта и не читает автоматически прежний `memory/gtd/`.

## Установка в Codex

Добавьте [публичный форк](https://github.com/Xerz/LLM-GTD-RU) в Codex и установите плагин:

```text
codex plugin marketplace add https://github.com/Xerz/LLM-GTD-RU.git
codex plugin add llm-gtd-ru@llm-gtd
```

Эти команды доступны в версиях Codex с поддержкой плагинов. Если `codex plugin` отсутствует в вашей установленной CLI-версии, добавьте репозиторий через каталог плагинов Codex Desktop или обновите CLI.

Если вы уже работаете в локальной копии этого проекта, можно добавить её как marketplace:

```text
codex plugin marketplace add /путь/к/папке/LLM-GTD
codex plugin add llm-gtd-ru@llm-gtd
```

Плагин также можно найти в каталоге Codex по имени **LLM-GTD на русском** после добавления marketplace. Установка плагина не создаёт личные списки внутри пакета: они появляются в том рабочем проекте, где вы попросите Codex запустить GTD.

Для коротких вызовов в `plugins/llm-gtd-ru/prompts/` лежат восемь русских prompt-файлов: общий `gtd-ru` и отдельные вызовы для настройки, сбора, уточнения, обновления, организации, выбора действия и обзора. Это необязательная ручная установка в каталог пользовательских prompts Codex; обычные фразы из примеров ниже работают через плагин без неё.

## Первый запуск

Откройте в Codex папку, где хотите хранить свои списки, и напишите:

> Настрой мою систему GTD на русском в этом проекте.

Появится `memory/gtd-ru/` с девятью списками. Повторная настройка сохранит существующее содержимое. Затем можно писать обычными словами:

- «Запиши: на следующей неделе связаться с врачом насчёт результатов».
- «Разбери входящие и предложи конкретные следующие шаги».
- «Я отправил документы; теперь жду ответа Анны».
- «У меня 20 минут и мало сил. Что сейчас сделать?»
- «Проведи еженедельный обзор моих дел».

Один новый пункт сначала сохраняется во входящих, затем обычно уточняется. При массовой выгрузке мыслей сначала сохраняется весь список. Обновление уже существующего дела меняет его состояние, а не создаёт дубль.

## Состав

`plugins/llm-gtd-ru/` содержит манифест, входной навык `gtd-ru`, семь рабочих сценариев, справочники, русские шаблоны и скрипт инициализации/обзора. Marketplace этого репозитория находится в `.agents/plugins/marketplace.json`. Старый плагин `llm-gtd` остаётся в проекте как исходная реализация.

Внутри рабочего проекта русская версия создаёт `inbox.md`, `next-actions.md`, `projects.md`, `waiting-for.md`, `calendar.md`, `someday-maybe.md`, `reference.md`, `horizons.md` и `product-ideas.md`. Их заголовки, поля и пояснения полностью русские. Отдельной миграции из `memory/gtd/` нет; если она нужна, попросите Codex разобрать исходные пункты вместе с вами.

Событие с определённой датой и временем может быть внесено во внешний календарь, если в вашей сессии доступен календарный инструмент. Перед записью Codex проверяет занятость, а после записи сообщает об успехе только при подтверждении инструмента. Когда провайдер недоступен, запись остаётся в `calendar.md` как требующая переноса. Обычные задачи в календарь не попадают.

## Локальная проверка

Из нужного рабочего проекта запустите:

```text
python3 /путь/к/LLM-GTD/plugins/llm-gtd-ru/skills/gtd-ru/scripts/gtd.py init
python3 /путь/к/LLM-GTD/plugins/llm-gtd-ru/skills/gtd-ru/scripts/gtd.py status
python3 /путь/к/LLM-GTD/plugins/llm-gtd-ru/skills/gtd-ru/scripts/gtd.py review-prep
```

`status` и `review-prep` только читают списки. Для пересылки другу есть короткий текст в [TELEGRAM.md](TELEGRAM.md).
