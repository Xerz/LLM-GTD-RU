# LLM-GTD на русском для Codex

[Исходный LLM-GTD](https://github.com/mikonos/LLM-GTD) · [Английский README оригинала](README.en.md) · [Короткая инструкция для Telegram](TELEGRAM.md)

LLM-GTD — система для ведения обязательств по методу GTD вместе с Codex. Дела и проекты хранятся в обычных Markdown-файлах, а Codex помогает разобрать входящие, сформулировать следующий шаг, поддерживать списки в актуальном состоянии и проводить обзор. Эта версия написана по-русски и предназначена для **Codex App**. Исходный плагин в форке сохранён.

## Как это выглядит

> **Вы:** Хочу помочь близкому человеку попробовать занятия.
>
> **Codex:** Записывает желаемый результат как проект и предлагает первый шаг: «Поговорить 10 минут: интересно ли это человеку, какие есть ограничения и сколько времени он готов уделять занятиям». Никуда не записывает человека и никому не пишет.

Позже вы возвращаетесь:

> **Вы:** Поговорили. Ему интересно, подойдут два занятия в неделю примерно по часу.
>
> **Codex:** Убирает завершённый разговор из активных действий, сохраняет новые обстоятельства и предлагает следующий шаг: «Сравнить два-три варианта по времени, цене, расстоянию и условиям пробного занятия». Приблизительную длительность помечает как требующую уточнения, если она важна для выбора.

Проект без текущего шага легко забыть. Система хранит обязательство между разговорами; вы сообщаете, что произошло, а Codex обновляет списки.

## Коротко о системе

Обычный список дел теряет пользу, когда входящие не разобраны, действия сформулированы расплывчато, у проектов нет следующего шага и обзор откладывается. LLM-GTD поддерживает весь цикл: сбор → уточнение → организация → обзор → выбор действия.

- Состояние хранится в девяти файлах `memory/gtd-ru/*.md` внутри **вашего рабочего проекта**.
- Один новый пункт сначала попадает во входящие, затем обычно уточняется. Массовая выгрузка мыслей сначала сохраняется целиком.
- Отчёт «сделал», «получил ответ» или «перенёс» обновляет существующую запись.
- Codex готовит варианты следующих шагов и обзор; решение, брать ли обязательство и что важнее, остаётся за вами.
- Календарь содержит только дела с жёсткой привязкой к дате или времени. Успешная внешняя запись не дублируется в локальном списке.

## Зачем это нужно

Одни навыки для агентов помогают только очистить входящие или провести еженедельный обзор. Другие пытаются стать большой системой управления всей жизнью. LLM-GTD сосредоточен на повседневных обязательствах: зафиксировать входящее, понять его смысл, сохранить конкретное напоминание, возвращаться к нему и своевременно обновлять состояние.

Codex берёт на себя формулировки, поиск зависших проектов и механическую работу со списками. Вы определяете цели, обещания и окончательный результат. Доверие к системе возникает, когда её записи соответствуют реальности.

## Что умеет плагин

| Намерение | Сценарий | Результат |
|---|---|---|
| Настроить систему | Инициализация | Создаёт девять русских списков и проверяет состояние, не переписывая существующие файлы. |
| Записать мысль или дело | Сбор | Сначала сохраняет исходную формулировку во входящих; небольшое число пунктов обычно сразу уточняет. |
| Разобрать входящие | Уточнение | Определяет следующий шаг, проект, ожидание, календарное обязательство, справку или отложенную возможность. |
| Сообщить об изменении | Обновление | Закрывает сделанное, продвигает проект, учитывает ответ, перенос или отмену. |
| Навести порядок | Организация | Находит дубли, отсутствующие связи и проекты без текущего шага. |
| Решить, что делать сейчас | Выбор действия | Показывает несколько подходящих вариантов с учётом условий, времени, энергии и целей. |
| Посмотреть на всю систему | Еженедельный обзор | Готовит сводку, обновляет списки и выносит на ваше решение вопросы о приоритетах. |

Сценарии описаны в [навыке плагина](plugins/llm-gtd-ru/skills/gtd-ru/SKILL.md). Можно писать обычными словами; отдельную команду выбирать не требуется.

## Где хранятся дела

| Файл в `memory/gtd-ru/` | Содержание |
|---|---|
| `inbox.md` | Ещё не разобранные записи. |
| `next-actions.md` | Конкретные действия, выполнимые за один шаг, с оценкой времени и необходимыми условиями. |
| `projects.md` | Результаты, которым нужно больше одного шага; каждый активный проект связан с действием или ожиданием. |
| `waiting-for.md` | Что, от кого и с какого времени вы ждёте. |
| `someday-maybe.md` | Возможности, которые пока не стали обязательствами. |
| `calendar.md` | Запасные записи о жёстких датах и встречах, когда внешний календарь недоступен. |
| `reference.md` | Справка и материалы для активных проектов. |
| `horizons.md` | Цели, принципы и области ответственности. |
| `product-ideas.md` | Продуктовые возможности и гипотезы; активная работа по ним видна в проектах или действиях. |

Содержимое, заголовки и поля новых файлов написаны по-русски. Латинские имена файлов нужны для стабильных ссылок между списками. Русская версия использует отдельную папку и автоматически не переносит записи из `memory/gtd/` исходного плагина.

## Как это устроено

```text
Вы сообщаете о намерении или изменении
        ↓
Навык gtd-ru выбирает сценарий
        ↓
Codex читает и обновляет Markdown-списки в memory/gtd-ru/
        ↓
Во время обзора проверяет проекты, ожидания, календарь и цели
```

Плагин содержит инструкции и шаблоны. Личные списки появляются в той папке, которую вы выбрали для своих дел; они не входят в скачанный плагин. Дополнительный календарный провайдер в пакет не включён: Codex использует его, только если он уже подключён и доступен в вашей сессии. Если такого доступа нет, `calendar.md` служит запасным списком с явной пометкой о необходимости переноса.

Исходный LLM-GTD поддерживает Claude Code, Cursor и Codex. **Русская адаптация этого форка рассчитана на Codex App.** Исходные многоплатформенные файлы сохранены для сравнения и дальнейшей работы.

## Чем этот подход отличается

- **Полный цикл GTD.** Система не заканчивается записью во входящие: она помогает уточнять, выполнять и пересматривать обязательства.
- **Открытое состояние.** Списки — обычные Markdown-файлы без отдельной базы данных.
- **Действия отделены от знаний.** Исследовательские заметки и самостоятельные идеи не превращаются автоматически в задачи.
- **Решения остаются за вами.** Codex может предложить действие или фокус недели, но не назначает вам новое обязательство по собственной инициативе.
- **Запись в календарь проверяется.** Перед созданием события Codex проверяет сведения и занятость. Об успехе внешней записи сообщает только после подтверждения инструмента.

## Установка в Codex App

Этот форк распространяется через **marketplace репозитория**. Он не опубликован в общем каталоге плагинов OpenAI, поэтому простого поиска по всем плагинам до добавления репозитория недостаточно.

1. Откройте [репозиторий LLM-GTD-RU на GitHub](https://github.com/Xerz/LLM-GTD-RU), выберите **Code → Download ZIP** и распакуйте архив. Оставьте папку целиком: внутри должны быть `.agents/plugins/marketplace.json` и `plugins/llm-gtd-ru/`.
2. В Codex App добавьте распакованную папку **как локальный проект** и откройте его. Перезапустите приложение, чтобы оно обнаружило marketplace проекта.
3. Откройте **каталог плагинов** в Codex App. Выберите источник **LLM-GTD**, найдите **LLM-GTD на русском** (`llm-gtd-ru`) и нажмите **Установить**. В том же источнике есть исходный `llm-gtd` — выберите именно русскую версию.
4. Создайте **новую задачу** в папке, где хотите хранить свои дела, и напишите: «Настрой мою систему GTD на русском в этом проекте». Эта папка станет местом хранения `memory/gtd-ru/`.

Codex App обнаруживает marketplace в открытом репозитории и предлагает его в каталоге плагинов после перезапуска; этот порядок описан в [официальной документации OpenAI](https://developers.openai.com/plugins/build/plugins). Если источник не появился, проверьте, что открыта корневая распакованная папка с `.agents/plugins/marketplace.json`, а затем полностью перезапустите приложение.

После установки сохраните распакованную папку: она остаётся локальным источником плагина. Для получения новой версии скачайте свежий архив в ту же папку, перезапустите Codex App и обновите локальный плагин через каталог, если приложение предложит обновление.

## Что нужно для работы

- Codex App и доступ к локальной папке для списков.
- Python 3 для встроенного скрипта инициализации и сводки. Codex может вызвать его по инструкции навыка.
- По желанию — календарный инструмент в Codex, если нужно читать и записывать внешние события.

CLI, Claude Code и Cursor для установки русской версии не требуются.

## Первый запуск

После установки можно обращаться к плагину обычным русским текстом:

```text
Настрой мою систему GTD на русском в этом проекте.
Запиши: нужно продлить паспорт до летней поездки.
Разбери входящие и предложи следующий шаг для каждого пункта.
Я отправил документы, теперь жду ответа ведомства.
У меня 30 минут и мало сил. Что сейчас сделать?
Проведи еженедельный обзор дел.
```

Повторная инициализация не перезаписывает существующие списки. Быстрые шаблоны запросов лежат в `plugins/llm-gtd-ru/prompts/`; для обычной работы вручную устанавливать их не нужно.

## Пример разбора нескольких мыслей

Вы говорите:

> «Нужно спросить Машу о школьной справке, продлить паспорт, может быть научиться играть на пианино, сохранить налоговый документ».

Codex сначала сохраняет все четыре пункта во входящих, затем разбирает их как группу:

- Разговор с Машей превращается в конкретное действие или ожидание, в зависимости от того, кто должен сделать следующий шаг.
- Продление паспорта становится проектом, если для результата нужно несколько действий.
- Пианино попадает в отложенные возможности, если вы не решили заниматься этим сейчас.
- Налоговый документ становится справочным материалом, если нужно только сохранить его для будущего обращения.

Если из фразы нельзя уверенно понять, взяли ли вы на себя обязательство, Codex спрашивает, не подменяя ваше решение догадкой.

## Границы системы

- Входящие — место для сбора, а не окончательный список дел.
- Следующее действие должно описывать видимый шаг: «Отправить бухгалтеру файл» вместо «Разобраться с налогами».
- Активному проекту нужен следующий шаг или конкретное ожидание.
- Обычные дела не занимают календарь; там остаются только жёсткие даты и договорённости.
- Еженедельный обзор поддерживает соответствие списков реальности.
- Неподтверждённая запись во внешний сервис не объявляется успешной.
- Знания и исследовательские заметки хранятся отдельно от действий.
- Codex не отправляет сообщения другим людям и не принимает за вас решения о важных обязательствах без явной просьбы.
